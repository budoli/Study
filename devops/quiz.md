### 객관식

   - B. 배포 속도와 안정성을 함께 높인다.
   - C. 테스트를 모두 수동으로 진행한다.
   - D. 서버 접속을 금지한다.

2. Linux에서 현재 디렉터리의 파일 목록과 권한을 자세히 보는 명령어는? B
   - A. `pwd`
   - B. `ls -al`
   - C. `cd`
   - D. `curl`

3. 실행 권한을 부여하는 명령어로 알맞은 것은? A
   - A. `chmod +x deploy.sh`
   - B. `chown +x deploy.sh`
   - C. `curl +x deploy.sh`
   - D. `git +x deploy.sh`

### 주관식

4. CI와 CD의 차이를 한 문단으로 설명하라.
   - CI는 개발자들이 공유 저장소에 지속적으로 통합하여 자동으로 테스트를 하는것이고 테스트를 통과하게 되면 CD의 지속적 제공/배포로 서버에 올리고 사용하기 위해 사용하는 차이가 있다.
5. Git branch를 사용하는 이유를 설명하라.
   - 개발자들의 코드를 각각의 기능에서 동작을 확인하고 병합을 쉽게 하기 위해 사용한다. 
6. `curl http://localhost:8080` 명령어로 확인할 수 있는 것은 무엇인가?
   - 로컬 환경에서 실행이 되는지를 확인한다.

### 실습

7. `deploy.sh` 파일을 만든다고 가정하고, 다음 작업을 수행하는 스크립트 흐름을 글로 작성하라.
   - 최신 코드 가져오기
   - 빌드 실행
   - 앱 재시작
   - 상태 확인

## 정답

### 1주차

1. B
2. B
3. A
4. CI는 코드 변경 시 테스트와 빌드를 자동 실행하는 과정이고, CD는 검증된 결과물을 배포 가능한 상태 또는 실제 운영 환경까지 전달하는 과정이다.
5. 기능 개발을 main 코드와 분리해 안전하게 작업하고, 리뷰와 테스트 후 병합하기 위해 사용한다.
6. 로컬 8080 포트에서 실행 중인 서비스가 HTTP 요청에 응답하는지 확인할 수 있다.

### 2주차

1. B
2. A
3. B
4. 코드 변경으로 기존 기능이 깨졌는지 빠르게 확인하고, 문제가 있는 코드를 main에 합치기 전에 막기 위해서다.
5. 코드 저장소에 민감 정보가 노출될 수 있고, 환경별 설정 변경이 어려워지기 때문이다.
6. 백엔드, DB, Redis처럼 여러 컨테이너를 함께 실행해야 할 때 필요하다.

### 3주차

1. B
2. A
3. D
4. 배포 후 문제가 생겼을 때 정상 버전으로 빠르게 되돌려 서비스 장애 시간을 줄이기 위해서다.
5. 사용자와 서버 사이의 통신을 암호화하고, 위조된 사이트가 아님을 증명하기 위해서다.
6. 장애 원인, 요청 흐름, 예외 내용을 확인할 수 있어 문제 해결의 핵심 자료가 된다.

### 4주차

1. A
2. A
3. A
4. Deployment는 Pod의 개수와 업데이트를 관리하고, Service는 변하는 Pod에 안정적으로 접근할 수 있는 주소를 제공한다.
5. ConfigMap은 일반 설정값, Secret은 비밀번호나 토큰 같은 민감 정보를 관리한다.
6. 로그는 사건의 기록이고, 메트릭은 시스템 상태를 숫자로 표현한 값이다.
