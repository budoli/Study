## Day 30. AI Prompt 요청 저장 API 만들기

### 목표

AI 백엔드로 넘어가기 전, 사용자의 프롬프트 요청을 저장하는 API를 만듭니다.

### 요구사항

- `PromptRequestEntity`를 만든다.
- 필드는 `id`, `userId`, `prompt`, `status`, `createdAt`을 가진다.
- `POST /prompt-requests` API를 만든다.
- 요청 body는 `prompt`를 가진다.
- 요청 헤더 `X-USER-ID`로 사용자 id를 받는다.
- 생성 시 status는 `PENDING`으로 저장한다.
- `GET /prompt-requests`로 내 요청 목록을 조회한다.

### 완료 기준

- 프롬프트 요청이 DB에 저장된다.
- 사용자별로 목록이 분리된다.
- status 기본값이 `PENDING`이다.
- Controller 테스트 또는 Service 테스트 중 하나 이상 작성한다.

### 힌트

- 아직 실제 AI API를 호출하지 않는다.
- 이번 과제의 핵심은 "AI 요청을 받을 백엔드 구조"를 만드는 것이다.
- status는 문자열보다 enum으로 시작해보는 것이 좋다.

### 회고 질문

- AI 기능을 바로 호출하지 않고 요청 저장부터 만드는 이유는 무엇인가?
- status가 필요한 이유는 무엇인가?
- 나중에 실제 AI 응답을 저장하려면 어떤 필드가 더 필요할까?
