# Day 014 - 문서 검색 CLI 만들기

## 오늘의 목표

사용자가 입력한 검색어를 TF-IDF 벡터로 바꾸고, 문서들과의 cosine similarity를 계산해서 가장 가까운 문서를 찾는다.

## 전체 흐름

```text
문서 읽기
-> 검색어 입력
-> 빈 검색어 처리
-> 문서 TF-IDF 벡터화
-> 검색어 TF-IDF 벡터화
-> cosine similarity 계산
-> 가장 유사한 문서 출력
```

## 배운 개념

| 개념 | 설명 |
| --- | --- |
| `input()` | 사용자에게 검색어를 입력받는다. |
| `strip()` | 입력값 앞뒤 공백을 제거한다. |
| `TfidfVectorizer` | 문서와 검색어를 TF-IDF 벡터로 바꾼다. |
| `fit_transform()` | 문서들로 vocabulary를 만들고 문서 벡터를 만든다. |
| `transform([query])` | 기존 vocabulary 기준으로 검색어를 벡터화한다. |
| `cosine_similarity()` | 검색어와 문서 벡터 사이의 유사도를 계산한다. |
| `argmax()` | 가장 높은 유사도 점수의 위치를 찾는다. |

## 작성한 코드

```python
"""Day 014 - Document search CLI."""

from pathlib import Path
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity


def main():
    doc_path = ["data/sample_docs/day014_doc1.txt", "data/sample_docs/day014_doc2.txt", "data/sample_docs/day014_doc3.txt"]

    documents = [Path(path).read_text(encoding="utf-8") for path in doc_path]

    query = input("검색어를 입력하세요: ").strip()

    if not query:
        print("검색어를 입력하세요.")
        raise SystemExit

    vectorizer = TfidfVectorizer()
    text_vector = vectorizer.fit_transform(documents)
    query_vector = vectorizer.transform([query])

    similarity = cosine_similarity(text_vector, query_vector)
    best_index = similarity.argmax()

    print("문서별 유사도:")

    for index, similar in enumerate(similarity, start=1):
        print(f"문서 {index}: {similar[0]:.4f}")
    print()
    print("가장 유사한 문서:")
    print(f"문서 번호: {best_index+1}")
    print(f"유사도: {similarity.max():.4f}")
    print(f"내용: {documents[best_index]}")


if __name__ == "__main__":
    main()
```

## 핵심 정리

- Day 011은 질문이 코드에 고정되어 있었고, Day 014는 `input()`으로 검색어를 받는다.
- 검색어는 빈 문자열일 수 있으므로 `strip()` 후 확인해야 한다.
- `query_vector = vectorizer.transform([query])`처럼 검색어 하나도 리스트로 감싸야 한다.
- `transform(query)`처럼 문자열만 넘기면 `ValueError`가 발생한다.
- `fit_transform()`은 문서에 사용하고, `transform()`은 검색어에 사용한다.
- 가장 유사한 문서 번호를 출력할 때는 `best_index + 1`을 사용한다.

## 헷갈렸던 점

| 잘못된 코드 | 문제 | 수정 |
| --- | --- | --- |
| `vectorizer.transform(query)` | 문자열 하나를 직접 넘겨서 오류가 난다. | `vectorizer.transform([query])` |
| `input("검색어를 입력하세요.")` | 빈 검색어일 때 다시 입력을 기다린다. | `print("검색어를 입력하세요.")` |
| `document search answer` 검색 | 문서의 `documents`, `searches`, `answers`와 정확히 일치하지 않아 점수가 0일 수 있다. | `documents answers context`처럼 실제 단어와 맞춰 테스트한다. |

## 오류 정리

```text
ValueError: Iterable over raw text documents expected, string object received.
```

이 오류는 `TfidfVectorizer.transform()`에 문자열 하나를 그대로 넣었을 때 발생한다.

```python
query_vector = vectorizer.transform(query)
```

검색어 하나도 문서 리스트처럼 감싸야 한다.

```python
query_vector = vectorizer.transform([query])
```

## 개선 포인트

검색 구조를 더 자연스럽게 표현하려면 질문 벡터를 앞에 둘 수 있다.

```python
similarity = cosine_similarity(query_vector, text_vector)[0]
best_index = similarity.argmax()
```

그러면 반복문도 더 간단해진다.

```python
for index, score in enumerate(similarity, start=1):
    print(f"문서 {index}: {score:.4f}")
```

## 한계

- 기본 TF-IDF는 `document`와 `documents`를 같은 단어로 보지 않는다.
- `search`와 `searches`도 다르게 처리된다.
- 의미가 비슷한 단어를 찾는 검색은 아직 어렵다.
- 이후 임베딩 검색을 배우면 의미 기반 검색이 가능해진다.
