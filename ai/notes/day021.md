# Day 021 - embedding 기반 문서 검색

## 오늘의 목표

여러 문서를 chunk로 나눈 뒤, 질문과 가장 의미가 비슷한 chunk를 embedding similarity로 찾는다.

## Embedding 검색

Embedding은 문장이나 문서를 숫자 벡터로 바꾼 것이다.

비슷한 의미를 가진 문장은 벡터 공간에서도 가까운 위치에 놓인다.

```text
질문 -> embedding
chunk text -> embedding
cosine similarity 계산
점수가 높은 chunk 선택
```

## 전체 흐름

```text
문서 목록 준비
-> 문서 하나씩 읽기
-> chunk_size, overlap 설정
-> 문서를 overlap 방식으로 chunking
-> chunk마다 source, chunk_id, text 저장
-> chunk text만 모아서 embedding 생성
-> 질문 embedding 생성
-> cosine similarity 계산
-> 점수 높은 순서로 정렬
-> Top 3 출력
```

## 핵심 개념

| 개념 | 설명 |
| --- | --- |
| `SentenceTransformer` | 문장을 embedding vector로 바꿔주는 모델이다. |
| `model.encode()` | 문자열 리스트를 벡터로 변환한다. |
| `chunk_texts` | 검색 대상이 되는 chunk 본문 리스트이다. |
| `query_embedding` | 질문을 벡터로 바꾼 값이다. |
| `chunk_embeddings` | 모든 chunk text를 벡터로 바꾼 값이다. |
| `cosine_similarity` | 두 벡터가 얼마나 비슷한지 계산한다. |
| `score` | 질문과 chunk의 의미적 유사도 점수이다. |

## 작성한 코드 흐름

```python
chunk_texts = [chunk["text"] for chunk in chunks]

chunk_embeddings = model.encode(chunk_texts)
query_embedding = model.encode([quest])

similarities = cosine_similarity(query_embedding, chunk_embeddings)[0]
```

이 부분이 Day 021의 핵심이다.

질문은 하나이기 때문에 `model.encode([quest])`처럼 리스트로 감싸서 넣는다.

chunk는 여러 개이기 때문에 `chunk_texts` 리스트 전체를 embedding한다.

## 결과 만들기

```python
results = []

for chunk, score in zip(chunks, similarities):
    results.append(
        {
            "source": chunk["source"],
            "chunk_id": chunk["chunk_id"],
            "score": score,
            "text": chunk["text"],
        }
    )
```

`zip(chunks, similarities)`를 사용하면 chunk metadata와 해당 chunk의 유사도 점수를 함께 묶을 수 있다.

검색 결과에서는 text만 중요한 것이 아니라, 나중에 출처 표시를 위해 `source`, `chunk_id`도 같이 유지해야 한다.

## 정렬과 Top 3

```python
results = sorted(results, key=lambda x: x["score"], reverse=True)
top_results = results[:3]
```

`score`가 높은 순서대로 정렬한 뒤 앞에서 3개만 가져온다.

`reverse=True`를 사용해야 점수가 높은 결과가 먼저 나온다.

## 헷갈렸던 점

| 잘못된 접근 | 문제 | 올바른 접근 |
| --- | --- | --- |
| `model.encode(path)` | 파일 경로 문자열을 embedding하게 된다. | `model.encode(chunk_texts)` |
| chunk 생성 중 similarity 계산 | 아직 전체 chunk embedding이 준비되지 않았다. | chunk를 모두 만든 뒤 계산 |
| `score`에 배열 전체 저장 | chunk별 점수가 아니라 전체 점수가 들어갈 수 있다. | `for chunk, score in zip(...)` |
| 전체 결과 출력 | 검색 결과가 너무 많아진다. | 정렬 후 Top 3만 출력 |

## 중요한 기준

검색 대상은 파일 경로가 아니라 문서 내용이다.

```python
text = Path(path).read_text(encoding="utf-8")
chunk_text = text[start:end]
```

embedding해야 하는 것은 `path`가 아니라 `chunk_text`이다.

```text
좋은 검색 대상: chunk_text
나쁜 검색 대상: 파일 경로 문자열
```

## chunk_size와 overlap

이번 문제에서는 다음처럼 설정했다.

```python
chunk_size = 100
overlap = 20
step = chunk_size - overlap
```

`chunk_size`는 한 chunk에 들어갈 글자 수이고, `overlap`은 다음 chunk와 겹치게 할 글자 수이다.

`step`은 실제로 다음 chunk를 시작할 간격이다.

```text
step = chunk_size - overlap
```

## RAG와의 연결

Day 020에서는 chunk에 metadata를 붙였다.

Day 021에서는 그 chunk들을 embedding해서 검색했다.

RAG의 검색 단계는 결국 다음 구조로 이어진다.

```text
사용자 질문
-> 질문 embedding
-> 문서 chunk embedding과 비교
-> 관련 chunk Top K 검색
-> 검색된 chunk와 출처를 답변 생성에 사용
```

Day 021은 RAG에서 retriever의 가장 기본 형태이다.

## 개선 포인트

사용하지 않는 변수는 제거하는 것이 좋다.

```python
embeddings = model.encode([quest])
```

현재 코드에서는 아래의 `query_embedding`을 사용하므로 위 변수는 필요하지 않다.

```python
query_embedding = model.encode([quest])
```
