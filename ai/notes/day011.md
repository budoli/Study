# Day 011 - 질문과 가까운 문서 찾기

## 오늘의 목표

사용자 질문과 가장 가까운 문서를 TF-IDF 벡터와 cosine similarity로 찾는다.

## 전체 흐름

```text
문서 읽기
-> 문서 TF-IDF 벡터화
-> 질문 TF-IDF 벡터화
-> 질문과 문서들의 cosine similarity 계산
-> 가장 점수가 높은 문서 출력
```

## 배운 개념

| 개념 | 설명 |
| --- | --- |
| `TfidfVectorizer` | 문서와 질문을 TF-IDF 벡터로 바꾼다. |
| `fit_transform()` | 문서를 보고 vocabulary를 만든 뒤 벡터로 변환한다. |
| `transform()` | 이미 만들어진 vocabulary 기준으로 새 텍스트를 벡터화한다. |
| `cosine_similarity()` | 두 벡터가 얼마나 비슷한 방향을 갖는지 계산한다. |
| `argmax()` | 가장 큰 값의 위치를 찾는다. |

## 작성한 코드

```python
from pathlib import Path
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

file_path = [
    "data/sample_docs/day011_doc1.txt",
    "data/sample_docs/day011_doc2.txt",
    "data/sample_docs/day011_doc3.txt"
]

documents = [
    Path(path).read_text(encoding="utf-8")
    for path in file_path
]

question = [
    "How does RAG find useful documents?"
]

vectorizer = TfidfVectorizer()
text_vector = vectorizer.fit_transform(documents)
question_vector = vectorizer.transform(question)

similarities = cosine_similarity(text_vector, question_vector)
best_index = similarities.argmax()

print(similarities)

print("질문:")
print("How does RAG find useful documents?")
print()
print("문서별 유사도:")
for index, similar in enumerate(similarities, start=1):
    print(f"문서 {index}: {similar[0]:.4f}")
print()
print("가장 유사한 문서:")
print(f"문서번호: {best_index + 1}")
print(f"유사도: {similarities.max():4f}")
print(f"내용: {documents[best_index]}")
```

## 핵심 정리

- 문서들은 `fit_transform()`으로 벡터화한다.
- 질문은 `transform()`으로 벡터화한다.
- 이유는 문서들로 만든 vocabulary 기준에 맞춰 질문을 변환해야 하기 때문이다.
- `cosine_similarity()`는 질문 벡터와 문서 벡터 사이의 유사도를 계산한다.
- 점수가 가장 높은 문서가 질문과 가장 가까운 문서이다.
- `argmax()`는 가장 높은 점수의 index를 반환한다.
- Python index는 0부터 시작하므로 문서 번호로 출력할 때는 `best_index + 1`을 사용한다.

## `fit_transform()`과 `transform()` 차이

| 코드 | 역할 |
| --- | --- |
| `fit_transform(documents)` | 문서들을 보고 vocabulary를 만든 뒤 문서 벡터를 만든다. |
| `transform(question)` | 기존 vocabulary 기준으로 질문 벡터를 만든다. |

질문에 `fit_transform()`을 다시 쓰면 문서와 질문이 서로 다른 vocabulary 기준으로 벡터화될 수 있다.

검색에서는 반드시 같은 기준의 벡터 공간에서 비교해야 한다.

## 개선 포인트

현재 코드도 정상 동작하지만, 검색 구조를 더 자연스럽게 표현하려면 질문 벡터를 앞에 둘 수 있다.

```python
similarities = cosine_similarity(question_vector, text_vector)[0]
```

이렇게 하면 결과가 1차원 배열로 나온다.

```python
for index, score in enumerate(similarities, start=1):
    print(f"문서 {index}: {score:.4f}")
```

점수 출력도 아래처럼 소수점 4자리 형식이 더 명확하다.

```python
print(f"유사도: {similarities.max():.4f}")
```

## 헷갈릴 수 있는 점

| 코드 | 의미 |
| --- | --- |
| `question = ["..."]` | `transform()`은 여러 문서를 받는 형태라 리스트로 감싼다. |
| `text_vector` | 문서들의 TF-IDF 벡터이다. |
| `question_vector` | 질문의 TF-IDF 벡터이다. |
| `cosine_similarity(text_vector, question_vector)` | 각 문서와 질문의 유사도를 계산한다. |
| `similarities.argmax()` | 가장 높은 유사도 위치를 찾는다. |
| `documents[best_index]` | 가장 유사한 문서 내용을 가져온다. |
