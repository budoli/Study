# Day 020 - chunk에 metadata 붙이기

## 오늘의 목표

두 문서를 overlap 방식으로 chunking하고, 각 chunk에 출처 정보를 metadata dictionary로 붙인다.

## Metadata

Metadata는 chunk 본문 외에 그 chunk를 설명하는 정보이다.

RAG에서는 검색 결과에 출처를 보여주기 위해 metadata가 필요하다.

```text
chunk text + source + chunk_id + start + end
```

## 전체 흐름

```text
문서 목록 준비
-> 문서 하나씩 읽기
-> overlap chunking
-> chunk마다 metadata dictionary 생성
-> chunks 리스트에 저장
-> 전체 chunk 개수 출력
-> metadata와 text 출력
```

## 배운 개념

| 개념 | 설명 |
| --- | --- |
| `source` | chunk가 나온 파일 경로이다. |
| `chunk_id` | 파일 안에서 몇 번째 chunk인지 나타낸다. |
| `start` | chunk 시작 위치이다. |
| `end` | chunk 끝 위치이다. |
| `text` | 실제 chunk 내용이다. |
| dictionary | key-value 형태로 구조화된 데이터를 저장한다. |

## 작성한 코드

```python
"""Day 020 - Metadata and sources."""

from pathlib import Path


def main():
    doc_files = ["data/sample_docs/day020_doc1.txt", "data/sample_docs/day020_doc2.txt"]

    chunk_size = 80
    overlap = 20
    chunks = []

    step = chunk_size - overlap

    for path in doc_files:
        text = Path(path).read_text(encoding="utf-8")

        for chunk_id, start in enumerate(range(0, len(text), step), start=1):
            end = start + chunk_size

            chunk_text = text[start:end]

            if chunk_text:
                chunks.append({
                    "source": path,
                    "chunk_id": chunk_id,
                    "start": start,
                    "end": end,
                    "text": chunk_text
                })

    print(f"전체 chunk 개수: {len(chunks)}")
    for chunk in chunks:
        print(f"Source: {chunk['source']}")
        print(f"Chunk ID: {chunk['chunk_id']}")
        print(f"Start: {chunk['start']}")
        print(f"End: {chunk['end']}")
        print(f"Text:")
        print(chunk['text'])
        print()

if __name__ == "__main__":
    main()
```

## 핵심 정리

- Day 018~019에서는 chunk 내용만 만들었다.
- Day 020에서는 chunk에 출처 정보를 함께 저장한다.
- `chunks`는 여러 chunk dictionary를 담는 리스트이다.
- `chunks.append({...})`로 dictionary를 리스트에 추가한다.
- `chunks = {...}`처럼 작성하면 리스트가 dictionary로 바뀌어 버린다.
- 먼저 모든 chunk를 만든 뒤, 마지막에 `for chunk in chunks`로 출력하는 구조가 좋다.

## 중요한 코드

```python
chunks.append({
    "source": path,
    "chunk_id": chunk_id,
    "start": start,
    "end": end,
    "text": chunk_text
})
```

이 코드는 chunk 본문과 출처 정보를 하나의 dictionary로 묶어 저장한다.

```python
for chunk in chunks:
    print(f"Source: {chunk['source']}")
```

저장된 metadata는 dictionary key로 꺼내서 출력한다.

## 헷갈렸던 점

| 잘못된 코드 | 문제 | 수정 |
| --- | --- | --- |
| `Path(doc_files)` | `doc_files`는 리스트라 한 번에 읽을 수 없다. | `for path in doc_files`로 하나씩 읽기 |
| `chunks = {...}` | 리스트에 추가하는 게 아니라 리스트 자체를 덮어쓴다. | `chunks.append({...})` |
| 반복문 안에서 전체 개수 출력 | chunk 생성 중간 개수가 출력된다. | 모든 chunk 생성 후 출력 |
| 변수로 바로 출력 | metadata 저장을 활용하지 못한다. | `for chunk in chunks`로 dictionary에서 꺼내 출력 |

## 실행 결과 핵심

```text
전체 chunk 개수: 4

Source: data/sample_docs/day020_doc1.txt
Chunk ID: 1
Start: 0
End: 80
Text:
...

Source: data/sample_docs/day020_doc2.txt
Chunk ID: 2
Start: 60
End: 140
Text:
...
```

두 문서에서 만들어진 chunk들이 하나의 `chunks` 리스트에 저장됐다.

## RAG와의 연결

RAG 답변에는 보통 출처가 필요하다.

```text
답변:
RAG는 외부 문서를 검색해서 답변에 활용하는 방식입니다.

출처:
- data/sample_docs/day020_doc1.txt # chunk 1
```

이 출처를 만들려면 검색 단계에서 chunk의 `source`와 `chunk_id`를 함께 유지해야 한다.

Day 020의 metadata 구조가 이후 RAG 검색 결과와 답변 출처 표시의 기반이 된다.

## 개선 포인트

dictionary 마지막 항목에도 쉼표를 붙이면 나중에 항목을 추가하기 쉽다.

```python
chunks.append({
    "source": path,
    "chunk_id": chunk_id,
    "start": start,
    "end": end,
    "text": chunk_text,
})
```

출력 전후에 빈 줄을 넣으면 결과가 더 보기 좋다.
