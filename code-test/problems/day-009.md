# Day 009 - 예산 상한선

## 난이도

입문

## 문제

여러 부서가 요청한 예산 배열 `requests`와 전체 예산 `budget`이 주어집니다.

모든 요청 예산을 그대로 배정할 수 있으면, 요청 예산 중 가장 큰 값을 반환하세요.

그렇지 않다면 정수 상한선 `cap`을 정해야 합니다. 각 부서에는 다음 규칙으로 예산을 배정합니다.

```text
배정 예산 = min(요청 예산, cap)
```

배정된 예산의 총합이 `budget` 이하가 되도록 하는 상한선 중 가장 큰 값을 반환하세요.

## 입력 형식

- `requests`: 길이가 1 이상 100,000 이하인 정수 배열
- 각 요청 예산은 1 이상 1,000,000 이하입니다.
- `budget`: 1 이상 1,000,000,000 이하인 정수

## 출력 형식

- 가능한 예산 상한선의 최대값

## 예시

```text
requests = [120, 110, 140, 150]
budget = 485
return 127
```

설명:

```text
상한선을 127로 정하면 배정 합계는 120 + 110 + 127 + 127 = 484입니다.
상한선을 128로 정하면 배정 합계는 120 + 110 + 128 + 128 = 486이 되어 전체 예산을 초과합니다.
```

```text
requests = [70, 80, 30, 40, 100]
budget = 450
return 100
```

설명:

```text
모든 요청 예산의 합이 320이므로 그대로 배정할 수 있습니다.
```

```text
requests = [10, 20, 30]
budget = 25
return 8
```

설명:

```text
상한선을 8로 정하면 8 + 8 + 8 = 24입니다.
상한선을 9로 정하면 9 + 9 + 9 = 27이 되어 초과합니다.
```

## 제한

- 상한선은 정수입니다.
- 시간 복잡도 `O(n log m)` 풀이를 목표로 하세요.
- `m`은 요청 예산 중 최댓값입니다.

## 힌트

상한선 `cap`을 정하면 총 배정 예산을 계산할 수 있습니다.

```text
sum(min(request, cap))
```

이 값이 `budget` 이하이면 `cap`을 더 키워볼 수 있고, 초과하면 `cap`을 줄여야 합니다.

이처럼 가능한 값의 범위를 반씩 줄이는 방식이 이분 탐색입니다.

## 체크 포인트

- 탐색 범위를 `0`부터 요청 예산의 최댓값까지 잡았는가?
- `sum <= budget`일 때 정답 후보를 갱신하고 더 큰 상한선을 탐색했는가?
- 합계가 커질 수 있으므로 Java에서는 `long`을 고려했는가?
