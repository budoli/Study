# Day 006 - 프린터 대기열

## 난이도

입문

## 문제

문서들의 중요도가 담긴 정수 배열 `priorities`와, 내가 알고 싶은 문서의 위치 `location`이 주어집니다.

프린터는 다음 규칙으로 문서를 출력합니다.

1. 대기열의 가장 앞에 있는 문서를 꺼냅니다.
2. 대기열에 꺼낸 문서보다 중요도가 높은 문서가 하나라도 있으면, 꺼낸 문서를 다시 대기열의 맨 뒤에 넣습니다.
3. 그렇지 않으면 해당 문서를 출력합니다.

`location` 위치에 있던 문서가 몇 번째로 출력되는지 반환하세요.

## 입력 형식

- `priorities`: 길이가 1 이상 100 이하인 정수 배열
- 각 중요도는 1 이상 9 이하입니다.
- `location`: 0 이상 `priorities.length - 1` 이하인 정수

## 출력 형식

- `location` 위치의 문서가 출력되는 순서

## 예시

```text
priorities = [2, 1, 3, 2]
location = 2
return 1
```

설명:

```text
중요도 3인 문서가 가장 먼저 출력됩니다.
```

```text
priorities = [1, 1, 9, 1, 1, 1]
location = 0
return 5
```

설명:

```text
중요도 9 문서가 먼저 출력되고, location 0의 문서는 다섯 번째로 출력됩니다.
```

## 제한

- 같은 중요도를 가진 문서가 여러 개 있을 수 있습니다.
- 처음 위치 `location`을 계속 추적해야 합니다.
- 시간 복잡도는 단순 시뮬레이션으로도 통과 가능한 범위입니다.

## 힌트

문서의 중요도뿐 아니라, 원래 인덱스도 함께 큐에 넣어야 합니다.

예를 들어 `[2, 1, 3, 2]`는 다음처럼 생각할 수 있습니다.

```text
[(2, 0), (1, 1), (3, 2), (2, 3)]
```

문서를 출력할 때마다 출력 순서를 1씩 증가시키고, 그 문서의 원래 인덱스가 `location`인지 확인하세요.

## 체크 포인트

- 중요도만 보고 원래 위치를 잃어버리지 않았는가?
- 더 높은 중요도가 남아 있는지 확인했는가?
- 출력된 문서의 원래 인덱스가 `location`인지 확인했는가?
